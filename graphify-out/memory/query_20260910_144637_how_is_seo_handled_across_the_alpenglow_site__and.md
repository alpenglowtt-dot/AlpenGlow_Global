# Q: How is SEO handled across the AlpenGlow site, and what silently undoes SEO edits?

## Answer

All public-page SEO is generated by scripts/seo-head.js and scripts/seo-homepage.js into marked blocks (SEO:BEGIN/END, SEOCONTENT, SEOFOOTER, SEOSTYLE, SEOPRELOAD); both are idempotent, so edit the script not the HTML. Two non-obvious traps found while doing this: (1) api.js loadPackagePage() hydrates package pages from data/bundle.js (window.ALPEN_DATA, which wins over data/pages/*.json) and assigns document.title = d.page_title, so a title optimized only in the HTML is overwritten on load - titles and the new meta_description field must be updated in the CMS records too; api.js was extended to also sync description/og:title/og:image from the CMS. (2) index.html and packages/package.css style the bare element selector nav{position:fixed|relative}, so a newly added <nav> for breadcrumbs or a footer link hub inherits it and renders as a fixed overlay on top of the footer - it needs an explicit position:static;display:block override. Also: 18 of 19 package pages were crawl-orphans because index.html only linked santorini/italy/bali statically and rendered the rest from a JS data array, fixed with a real footer link hub; compass.html was set noindex because it renders only a Verification Required gate to any unauthenticated visitor including Googlebot.
